# 交互设计 · 成员视图

> 成员的单页世界——名下 key 的调用日志、用量聚合、完全公开透明的支付参数。**R12 的交互落点**：含「日志行携带所属订阅/充值信息」的形态定案。页面无任何「应付」概念（分摊哲学裁决）。

|------|------|
| 状态 | 定稿（2026-10-01） |

## 1. 单页结构（自上而下，滚动即全部）

### 1.1 页头

成员名 + 一句话定位「你在本池的名下用量」（「你」= 该成员；页面文案以成员视角书写）

### 1.2 时间范围选择器

共性组件；默认最近 30 天，快捷项含「本订阅期间」

### 1.3 聚合卡（该时段总览）

- 总用量：次数 / quota / 美元（标注「按当时换算率」）
- **按来源分解**：订阅消耗 / 充值消耗（分段条）——回答「我的用量花在哪个池子」

### 1.4 支付参数卡（完全公开透明的落点）

该时段涉及的订阅与充值，**参数原貌**逐笔列出：

- 订阅：期间、订阅 ID、额度（quota + $）、金额（纯数字）
- 充值：支付时间、额度、金额
- 脚注：「支付参数对成员完全公开；币种由成员与作者约定」——透明裁决的界面声明

> **不出现**任何派生金额：无「折合人民币」、无「占比 × 金额」、无「应付」——账本是事实，算账是社交层的事。
>
> 空态：无登记的部署形态（纯用量模式，《总览与共性》§3.8）下该卡显示中性文案「暂无支付记录信息」——不设行动引导（不登记是合法使用形态）。

### 1.5 我的 key 列表

每 key 一张窄卡：`token_name`、数据截止（停滞标注）、该时段用量（次数 / quota / $）。

### 1.6 日志明细表

| 列 | 内容 |
|----|------|
| 时间 | 到秒（北京时间） |
| key | `token_name` |
| 模型 | `model_name` |
| 来源 | **来源徽章**：`订阅 #N` / `充值` / `未关联`（灰）——携带形态的第一层（一眼识别） |
| 用量 | quota + 美元双单位 |
| tokens | prompt + completion |

**携带形态定案（R12 悬置项的本设计结论）**：两层实现——

1. **行内徽章**（常驻）：来源类型 + 订阅编号，零噪声
2. **展开行**（点击徽章）：该笔支付的完整参数（期间 / 额度 / 金额 / 备注）——完整透明的第二层，按需展开不打扰

> 展开行降级：徽章对应的订阅**无支付记录**时，展开显示「该订阅无登记信息」（纯用量模式的常态，见《总览与共性》§3.8）；徽章显示「未关联」的行（日志缺 `subscription_id`）不可展开——两种空值场景各自归位，见 `usage_logs表字段设计.md` 3.6。

> 该形态随实现期真实数据核查（订阅编号同一性）后再终验；徽章文案预留「未关联」的正常位（健康指示语义）。

## 2. 状态与边界

| 场景 | 表现 |
|------|------|
| 该时段无日志 | 聚合区「该时段内无调用」+ 明细空态 |
| 名下无 key（刚开户） | 全页空态「作者尚未为你分配 key」 |
| 令牌失效/停用 | 任意请求 401 → 登录壳（「令牌无效或已停用」） |
| 旧令牌（作者重发后） | 同上——旧令牌即刻作废 |

## 3. 窄屏说明

成员可能用手机查看本页——但按《总览与共性》§3.5 的裁决：**不做移动端 UI 设计**，窄屏下依赖布局响应（区块纵向堆叠、宽度弹性）保证可读不崩；明细表保持表格形态，横向滚动即可。
