## 1. 结论总览

**全栈 TypeScript，一套语言贯穿前端与后端。**

| 层 | 选定 |
|----|------|
| 运行时与工具链 | **Bun**（runtime + 包管理 + 测试 + 打包一体化） |
| HTTP | **Hono** |
| 数据访问 | **Drizzle ORM** + postgres.js + **PostgreSQL** |
| 调度 | **独立进程 `apps/engine`**：手写 `setTimeout` 循环（细则见《同步引擎设计》） |
| 加密 | WebCrypto（Bun 原生） |
| 前端 | **Vue 3 + antdv-next + Vite** |

## 2. 语言：TypeScript 全栈

1. 前端横竖是 JS 家族（Vue 3）——前后端同语言，类型系统、模块、异步语义一份学完，DTO 类型前后端共用一份契约；
2. 作者点名学习目标（Bun + Hono + Drizzle + PostgreSQL）即 TS 生态；
3. R13 后续的 CFW 形态原生运行时也只有 JS/TS——全栈 TS 顺带保留了那扇门（现阶段不作为选型依据，零成本预留见 §5）。

## 4. 分层落地：monorepo（Bun workspaces）

```text
（仓库根）
├─ apps/
│  ├─ server/     # 母体后端：Hono serve 装配 · Drizzle/pg · 环境变量与密钥注入
│  ├─ engine/     # 同步引擎：独立进程（《同步引擎设计》）
│  └─ web/       # 前端：Vue 3 + antdv-next + Vite
├─ packages/
│  ├─ core/      # 业务核心：轮询与 request_id 去重 · 折算链 · 加密体系 · API 语义与 DTO 类型
│  └─ db/        # 数据访问层：Drizzle schema（pg 方言）+ 仓储 + 迁移 CLI
├─ scripts/      # 打包/构建 CLI（naku pack / build）
```

**依赖规则（单向）**：`apps/*` → `packages/db` → `packages/core`；core 导出的 DTO 类型可被 web 以纯类型依赖引用（前后端共用一份契约类型）。

**代码落点**：实现代码与设计文档同仓演进。

## 5. R14 预留：现阶段零成本，只为后续抽取不挖坑

R13 的 CFW 抽取版仍是长期裁决，功能全集实现后启动，届时按 R14「从母体抽业务核心、换基础设施层」执行。本稿只保留两条现阶段零成本、届时免重写的预留：

1. **Bun 纪律**：`packages/core` 只使用 TypeScript 标准库与 Web 标准 API（`fetch` / WebCrypto / `URL` / `TextEncoder` / `setTimeout` 等）；`Bun.*`、`bun:*`、`node:*` 与具体数据库驱动只出现在 `apps/*` 装配层、`packages/db` 与 `scripts/`——届时 CFW 形态的绑定物（D1 等）同样只落在新的装配层，core 原样搬运；
2. **方言不外泄**：pg 特有物（`jsonb` 等）只出现在 `packages/db` 的 schema 与仓储实现内，不进 core——届时补一份 SQLite 方言 schema 即可，core 与仓储接口不动。

Hono（双运行时可跑）与 WebCrypto 本身恰好与 CFW 兼容，属顺手之得，不构成现阶段约束。
