## 0. 平台定位与背景

**定位**：不依赖 NewAPI 平台管理员与用户体系的**独立计费平台**。上游只提供 sk-key 级接口——没有账单、没有分摊、没有历史回填，一切计费性质的能力（采集、归集、折算、分摊、账单）都必须由平台自身承载。上游接口的完整实证见 `docs/references/NewAPI-接口范围.md`。

**平台哲学（2026-09-29 裁决）**：**平台不做价值判断，只提供事实服务**——「谁该付谁多少钱」的分摊口径是人和人之间的事；平台提供分账所需的全部原材料（用量事实、来源标注、支付记录、多维统计），数字全部客观中立。

**背景**（三类问题促成当前设计阶段）：

1. **迭代部署成本**：服务器部署形态下每次迭代都需实例运营方手工升级，测试阶段迭代频繁而运营方无暇跟随 → 双形态交付（R13，已裁决）
2. **初版设计刻意收缩的部分**：管理面固定口令不妥（R11）、充值折算（R7）、多订阅处理（R8）
3. **已知设计问题**：错误行 `request_id` 去重（R15 必修项）

## 7. R13 的支撑材料：CFW 可行性调研（2026-09-29，developers.cloudflare.com 官方文档核实，五项全部无阻断）

| # | 调研点 | 结论（Workers Free / Paid） |
|---|--------|---------------------------|
| 1 | Cron 粒度与补偿 | `*/5 * * * *` 支持（最小每分钟）；UTC 执行；**单次执行上限 15 分钟**；`controller.scheduledTime` 可检测延迟；失败重试机制存在（`noRetry()` 可关）；Cron Events 留存最近 100 次调用（可观测） |
| 2 | D1 限制 | 单库 **500 MB / 10 GB**；每 Worker 调用查询数 **50 / 1000**；单条 SQL ≤ 100 KB、绑定参数 ≤ 100/语句；库为单线程（写入串行）——本项目低频批量写入无碍 |
| 3 | Workers 运行时 | CPU：**10 ms**（网络等待不计）/ 30 s（<1h 间隔 cron；≥1h 为 15 min）；外网子请求 **50 / 1000** 每调用；出站并发 6；Cron Triggers 每账号 5 / 250 |
| 4 | 免费额度 | Workers Free：10 万请求/天；D1 Free：读 500 万行/天、写 **10 万行/天**、存储 5 GB；**静态资产请求免费无限**（前端托管零成本） |
| 5 | 加密体系 | Workers 完整实现 Web Crypto：**HKDF ✓ / AES-256-GCM ✓ / HMAC-SHA256 ✓**（原生加速）——`SK_KEY_ENCRYPTION_SECRET` 体系可平移 |

**负载画像对照**（key 数按 10–25 估）：

- 每轮 cron：外网子请求 = 2 × key 数（Free 上限 50 → 最多 25 key）；CPU 主要花在 1000 条 JSON 解析 + SHA-256 指纹 + AES-GCM 解密——**Free 10 ms 是唯一贴线风险点**（实现期实测，超限则升 Paid）
- D1 写入：5 分钟一批、日增千行级 ≪ 10 万行/天；存储日增 MB 级 → Free 500 MB 可撑约两年，Paid 10 GB 富余
- 查询面：个人低频聚合查询 ≪ 500 万行读/天（时间范围需走索引避免全表扫描）
- 同步引擎防重入：D1 单线程天然串行化写入，多 cron 并发触发无竞态风险；每轮幂等（`request_id` 去重），失败重试零副作用

## 9. 裁决记录

### 2026-09-29 · 访问主体模型（R11 · R12 · 关联 R5）

**访问主体 = 作者 + 成员，一个模型两种凭证**（运营方完全信任，不设身份；CFW 版可将来叠加 Cloudflare Access 作为前置纵深，不作鉴权主体）。

**成员侧（成员视图）**：

- **成员实体（新增）**：基本用户字段（`id` / `name` 显示名 / `remark` 备注 / `status` 启停 / `created_at`）+ 受管理凭证（`token_hash` 哈希存储 + `token_issued_at`；生成时明文展示一次，可吊销、可重发）+ key 归属（`api_keys.member_id`，**1:N**，允许空——未归属 key 存在）
- **一层成员模型**：key 创建权始终在作者（唯一 NewAPI 账号持有人）；**归属登记即层级**——成员向下拼车 = 作者开新 key 挂其名下，平台不感知下级；算账口径 = 成员名下全部 key 的计费总和
- **成员视图**：登录壳（输入令牌 → sessionStorage，关标签失效）→ 自己关联的 key 列表 + 每 key 计费 + 聚合（应付部分随 R9 裁决展开）
- 成员侧无注册、无密码、无会话；令牌泄露处置 = 作者吊销重发（朋友信任关系下凭证事务经作者，路径短于自助改密）

**管理面侧（作者，唯一管理员）——最小登录体系**：

- **users 表**（单行：作者 `username` + `password_hash`）+ **sessions 表**（随机 256bit 令牌哈希存储、`expires_at` 如 7 天、登出即删，随时可踢）
- **密码哈希 = PBKDF2-SHA256**（WebCrypto 原生，高迭代）——Workers runtime 无 argon2/bcrypt，PBKDF2 是两形态统一实现（R14 的落地细节）
- **浏览器侧**：`HttpOnly + Secure + SameSite=Lax` cookie，路径限管理面——替代手动凭证管理
- **部署期初始化（空库双通道）**：初始用户名/密码经 env（母体）/ wrangler secret（CFW）传入；管理面入口幂等**三态判断**——非空 → 登录页；空库 + env 凭证在 → **静默落库**（部署完成即就绪，无抢注窗口；母体启动 / 首次请求检查，CFW 首次请求 / 首次 Cron 检查）；空库 + env 凭证无 → **引导页**设新密码（重置兜底通道）
- **初始凭证为引导性质**：仅空库时生效，此后改 env 不改密；**改密走登录后的表单**（旧密码验证 → 落库，登录体系的基本配套）；**env 凭证可留可删、无依赖**——留着：删 `users` 行即静默重建；删了：引导页当场设新密码（见 `users表字段设计.md` 3.1）；抢注窗口仅存在于「删 env + 删行」的重置瞬间
- 无注册、无找回（忘记密码 = 服务器改库，管理员特权）；登录节流为最小实现（失败延迟/计数）
- **基线三件套状态修正**：作者侧登录页与会话**解禁**（最小形态）；admin 角色不做（单管理员无角色引擎用武之地）；成员侧维持令牌无会话

**开放查看面裁撤**（同日裁决）：「凭 sk-key 查」入口取消——sk-key 明文从 web 界面消失（仅登记时输入一次、随即加密）；场景归位：**成员 → 令牌视图；作者 → 管理面**（key 清单下钻 + 全员总览面板，总览为新增设计项）

**审计日志（独立需求，与鉴权方案正交）**：管理面写操作（key 登记/启停、购买记录增删改、成员开户/停用、令牌签发/吊销、改密）逐条留痕：**操作类型、时间、操作者**（前向兼容多管理员扩展——审计是不可变历史，归属不能事后补写；系统触发事件如空库重建为 NULL）、关键内容摘要；属业务核心层，两形态共有。同理正交的还有同步引擎运行日志——记录语义两形态一致，落盘通道随形态（母体 stdout/journald，CFW Workers Logs）

### 2026-09-29 · 分摊哲学与原材料（R9 重定义 · R10 裁撤 · R6/R7 重定义 · R12 形态修正）

**平台不做价值判断，只提供事实服务**——「谁该付谁多少钱」是人和人之间的社交问题；平台提供分账所需的全部原材料，数字全部客观中立。

**裁掉**：

- **应付款计算与分摊口径**——「闲置额度归谁」这类没有客观答案的问题，平台不回答（「按占额度分摊」vs「按占总用量分摊」的口径之争随之消失）
- **期末账单快照与周期管理**（R10 裁撤）——周期 = 任意查询时段（订阅期间为预置选项），无平台侧账单
- **每行日志的实付分摊金额（`amount_rmb`）**——「quota 占比 × 实付」是分摊口径的派生值而非事实，且随购买记录修订漂移；明细行金额回归 **quota + 额度美元**（÷ `quota_per_unit`，`qpu_history` 时间线，纯客观单位换算）；基线「查看面金额口径 = 折算实付人民币」的设计作废

**保留与新增**：

- **支付记录**（订阅与充值同构）：支付金额 ↔ 额度的**比率关系**——**币种无关**（系统不预设人民币或其他币种，币种是使用者之间的约定）；订阅与充值两类支付事件统一建模（表结构与命名随 R15）
- **计费来源标注为一等维度**：`billing_source`（订阅 / 充值）随日志解析存储；按来源 / 成员 / key / 模型的任意时段多维聚合
- **充值登记**（R7 重定义）：与订阅同构——不做充值用量的金额分摊（原「池子加权平均」方案裁撤）
