## 1. 页面结构（自上而下）

### 1.1 健康带（页面顶部，常驻）

| 元素 | 内容 | 说明 |
|------|------|------|
| 引擎状态 | 「最近轮次：18 key，成功 16，失败 2」 | 失败数 > 0 时高亮并链到 Key 管理的失败筛选 |
| 全池数据截止 | 取全池 `log_synced_at` **最慢**（既定聚合语义） | 落后超过 2 小时 → 黄色预警「数据截止停滞——检查引擎日志」 |
| 未关联订阅分组 | 该时段内 `billing_source = subscription` 且 `subscription_id` 为空的量 | **正常恒为 0**；非零 → 红色提示（缺登记或上游行为变化）——健康指示器的可视化 |

> 健康带不主动轮询（打开页面刷新即可）；告警推送能力属 R4（延后），此处只做「打开页面即可见」的显形。

### 1.2 时间范围选择器

- 共性篇 §3.1 的核心组件；**默认最近 30 天**，快捷项含「本订阅期间」

### 1.3 按成员汇总区（主区块）

卡片栅格，每成员一张卡：

- 成员名（+备注 hover）
- 名下 key 数、该时段用量（次数 / quota / 美元）、**占全员比例条**（该时段内的事实占比）
- 数据截止（名下最慢）
- 「未归属（归作者）」作为一张固定的卡——无归属 key 的用量去向（`member_id IS NULL` 的聚合）

### 1.4 按 key 明细区

- 折叠表（默认收起，与按成员卡互不抢屏）：key 名、归属、状态、数据截止、该时段用量
- 行点击 → 跳转 Key 管理页该 key 详情
- 按「按来源」的分解以**分段条**呈现于表头上方：订阅消耗 / 充值消耗（该时段）

## 2. 交互流

| 动作 | 流程 |
|------|------|
| 切换时间范围 | 局部刷新全部区块（口径标注同步更新） |
| 点击健康带的失败数 | → Key 管理页，筛选「最近轮次失败」 |
| 点击成员卡 | → 该成员的 key 列表过滤视图（或成员管理页定位该成员） |

## 3. 空态

- 无任何 key：健康带显示「未登记任何 key」，主区块引导「去 Key 管理登记第一个」
- 有 key 无日志：各卡正常、用量为 0（空态与零值区分标注「该时段内无调用」）
