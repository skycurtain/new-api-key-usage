## 0. 这个功能是什么

**用 NAKU 自己按上游公式重算一次 `quota`，与日志里的 `quota` 比对。**

价值有两层：

1. 发现上游计费口径变化（模型改了倍率算法、切了计价模式）
2. 发现自己的理解有错（某类调用的字段含义与假设不符）

它**不产生金额**，只做核对。因此有一条贯穿全模块的契约：

> **只有 `status === "matched"` 才可向用户展示数字；`unmatched` / `unsupported` 只展示原因，不得把候选值当结果。**

## 1. 范围裁决（已定，2026-11-09）

覆盖范围：

```
文本调用（PostTextConsumeQuota 这一条结算路径）
  × 计价方式：倍率制 / 表达式计费
  × 语义：OpenAI / Anthropic
  × 计费构成：输入输出 token、缓存读、缓存写（含 5m/1h/12h 拆分）、分组倍率
```

其余一律 `unsupported`，共 **13 种**原因：

| reason | 触发 |
|---|---|
| `no_billing_info` | `other` 缺失 / 无计费字段 / 缺 `expr_b64` / base64 解不开 |
| `not_text_path` | 缺文本日志签名键（非 `GenerateTextOtherInfo` 产物） |
| `task` | `other.is_task`（MJ / 异步任务） |
| `realtime` | `other.ws`（实时语音） |
| `audio` | `other.audio`（音频 TTS/STT） |
| `fixed_price` | `model_price > 0`（按次固定价） |
| `image_tokens` | 含图片 token 项，或表达式引用 `img*` / `image_count` |
| `audio_tokens` | 含音频输入项，或表达式引用 `ai` / `ao` |
| `tool_surcharge` | 含 `tool_surcharges` |
| `expr_grammar` | 表达式词法 / 语法不合法 |
| `fixed_expr` | 表达式用了 `fixed()`（按次档位） |
| `expr_unsupported` | 构造 / 函数 / 运算符不在求值白名单（`detail` 带名字） |
| `expr_var` | 表达式引用了本模块不提供的变量 |

四条明确裁决（不变）：

1. **图片 / 音频 / 工具附加项不做**——即使公式已知、字段齐备也主动排除
2. **按次、语音、任务不做**——按次纯文本本可算，但不在范围；语音/音频可算但未实现
3. **不为将来预留**：不做"向后考虑"的扩展位
4. **不保留静态回归测试**：正确性由线上「验算结果 vs 日志 quota」的持续比对维持（作者裁决）

## 3. 上游实现调研结论（关键事实）

**上游没有自研求值器**——`pkg/billingexpr` 是 [`expr-lang/expr`](https://github.com/expr-lang/expr) 的封装，`go.mod` 钉死 **v1.17.8**（rc.49 的 `go.mod` 实测确认）。

自研部分只有五项：版本前缀解析（`v1:`）、编译缓存、AST 改写（请求倍率追踪）、变量提取、quota 换算与快照。

### 3.1 环境暴露的名字

**13 个变量**：`image_count` `p` `c` `len` `cr` `cc` `cc1h` `cc12h` `img` `img_cr` `img_o` `ai` `ao`

**17 个函数**：`tier` `fixed` `max` `min` `abs` `ceil` `floor` `hour` `minute` `weekday` `month` `day` `header` `param` `u` `has` `_trace`

**关键类型事实（本轮新增）**：`run.go` 把 env 全部填成 `float64`（`tier` 的签名是 `func(string, float64) float64`），`max`/`min`/`abs`/`ceil`/`floor` 直接绑 `math.*`。因此 JavaScript 的 number 语义与上游**逐位一致**：`/` 是浮点除、`%` 取余符号随被除数。这是整条链路上最容易踩空、也最省事的一处对齐。

### 3.2 结算换算

```go
quotaBeforeGroup = cost / 1_000_000 × QuotaPerUnit     // TaskUsageBilling 时不除 1e6
afterGroup       = common.QuotaRound(quotaBeforeGroup × GroupRatio)   // 四舍五入 + int32 饱和
```

这一层与本模块实现**完全一致**。

## 4. 核心矛盾（已解决）

原 `expression.ts` 是从 14 条真实表达式反推的 **250 行子集**，与 expr-lang 必然存在分歧。移植后改为「语法全量 + 语义白名单」，分歧面从"算错"变成"指名拒绝"。

### 4.1 原先已探明、现已对齐的分歧面

| 构造 | 原实现 | expr-lang | 现在 |
|---|---|---|---|
| `-2 ** 2` | 语法错误 | 合法，`-(2**2)` = -4 | ✅ 算出 -4 |
| `1 == "1"` | JS 为 true | 强类型 false | ✅ 算出 false |
| `3 in [1,2,3]` | 按下标判断 → false | true | 语法认识，求值指名拒绝 |
| `and` / `or` / `not` | 语法错误 | 合法 | ✅ 解析并求值 |
| `matches` / `nil` / lambda `#` | 语法错误 / ReferenceError | 合法 | 解析认识，求值指名拒绝 |
| `fixed()` / `max` / `min` / `hour` 等 | 未实现 | 合法 | `fixed` 拒绝；`max`/`min` 族已实现；其余指名拒绝 |

### 4.2 两个待修缺陷（均已修复）

1. **拒绝原因错误归因**：表达式用了 `fixed(...)` / `max(...)` 时，原实现抛「不支持的函数」，最终却报 `no_billing_info「缺可解析的 expr_b64」`——实际表达式完好，只是能力不支持。
   现在：`fixed` → `fixed_expr`；`param`/`header`/时间函数等 → `expr_unsupported` 且 `detail` 带名字。
2. **`v1:` 前缀无法处理**：上游正式格式是 `"v1:tier(...)"`，原词法会把它当标识符 + 冒号，报「末尾有多余记号」。
   现在：前缀在解析前剥掉；非 `v1` 的版本前缀单独拒绝。

### 4.3 移植后仍然存在的边界

- **`|||` 请求条件倍率**：日志能提供 `request_rules` 追踪，但那是**上游自己**的判定结果，用它去算等于拿答案验答案，不构成独立核对。故整条拒绝（`expr_unsupported`）。
- **比较链**：`a < b < c` 在上游会展开成 `(a < b) && (b < c)`，已实现；`==` `!=` `in` 等不成链，走普通左结合。
- **`??` 混写限制**：上游对 `a ?? b + c` 直接编译报错。因为这类表达式根本存不进上游，本模块**不复制**这道检查（`a ?? b + c` 会被解析成 `(a ?? b) + c`），不影响任何真实日志。

## 5. 语法层移植（已执行，方案 C）

**决策**：只移植**语法层**（lexer + Pratt parser + 直接解释 AST），**不做类型检查、不做编译器/VM**。

依据：日志里的表达式都是上游已编译通过的，类型检查对我们零收益，却是移植中最重的一块。

### 5.1 架构

```
日志表达式 ──▶ 门面 ──▶ lexer ──▶ parser ──▶ AST ──▶ 分析（白名单）
               │                                       └─ 拒绝：fixed_expr / expr_unsupported / expr_var
               ├─ 剥 v1: 前缀                          └─ 放行：7 个 token 变量
               └─ 切 |||（有则拒绝）                      ▼
                                                       解释器
```

原则：**语法全量、语义白名单**——解析器认识 `in`/`matches`/lambda，求值器遇到不在白名单的东西时给出**精确原因**，而不是笼统的"解析失败"。

### 5.3 能力白名单（最终形态）

| Tier | 内容 | 处理 |
|---|---|---|
| **1 实现** | 数字 / 字符串 / 布尔 / `nil`；`+ - * / % ** ^`；六种比较；`and` `or` `not` `&&` `\|\|` `!`；三元与 Elvis；`??`；括号；`tier()`；7 个 token 变量；`max` `min` `abs` `ceil` `floor` | 求值 |
| **2 解析但拒绝** | `in` / `not in` / `matches` / `not matches` / `contains` / `startsWith` / `endsWith` / `has`；数组 / 映射 / 成员访问 / 下标 / 切片 / 区间 | `expr_unsupported`，`detail` 带构造名 |
| **3 指名拒绝** | 集合内建（`filter` `map` `all` …）、lambda `#`、时间函数、`header` / `param` / `u` / `has()`、`fixed()`、`let` / `if` / `;`、管道 `\|`、`$env` | `expr_unsupported`；`fixed` 单独归 `fixed_expr` |

Tier 2/3 的共同点：与 token 量无关，或需要日志里不存在的外部语境——都在已定范围之外。

> Tier 1 里的 `max` / `min` / `abs` / `ceil` / `floor` 是**本轮新增的判断**：原计划没把它们归进哪一档。归 Tier 1 的理由是上游直接绑 `math.*`、只吃 token 数、与 `Math.*` 逐位一致，实现成本近乎为零；反过来拒绝它们会让本可算的表达式变成 `unsupported`。

### 5.5 语义对齐清单（实测项）

按上游规则逐条对拍，均已通过：

- `-2 ** 2` = -4、`2 ** 3 ** 2` = 512（幂右结合且高于一元负）
- `-a * b` = `(-a)*b`、`not a * b` = `not (a*b)`（一元 `not` 的 50 低于乘的 60）
- `3 < 2 < 1` = 0（比较链展开成 `&&`）
- `1 == "1"` = false（强类型）
- `-7 % 2` = -1（取余符号随被除数）
- `p ?? 5` 对非 nil 左值原样返回；`nil ?? 5` = 5
- `1 && 1` 不等于真（`&&` 只认布尔）
- 三元右结合、Elvis、`v1:` 前缀、`0x`/`0o`/`0b`、指数、前导点小数、两种注释

## 8. 本机环境注意事项

记录本次工作中反复遇到的摩擦，省下接手者的试错：

1. **沙箱内 `pwsh` 无法写工作区子目录与 `.git`**（ACL 问题，非仓库问题）。`write` / `edit` 工具正常；`git add` / `git commit` 需要一次性放行。**写代码只能走 `write` / `edit`，不能用 pwsh 重定向**
2. **`edit` 工具偶发 `ReplaceFileW EIO (Win32 1175)`**——重试即可（有时要连试两次），或改用整文件 `write`
3. **对同一文件的并行 `edit` 会互相冲突**——必须串行
4. **`curl` / `bun fetch` / `Invoke-WebRequest` 全部无法联网**（TLS 被拦：schannel `SEC_E_NO_CREDENTIALS`、bun `ECONNRESET`）。取上游源码**只能用 `web_fetch`**，它会把全文灌进上下文，所以大文件应交子任务先提炼再落盘
5. **临时验证脚本**放在 `%TEMP%\naku-replay\`，通过 `file:///` 绝对路径导入 `packages/core` 与 `packages/db/node_modules/postgres`；这些脚本不入库，可能被系统清理
6. Windows 上 `bun` 需在 `pwsh` 中运行（见 `AGENTS.md`「命令」）
