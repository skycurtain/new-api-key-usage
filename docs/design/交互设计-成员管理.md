## 1. 成员清单（页面主体）

列表上方轻量筛选：名称/备注搜索 · 状态（全部/启用/停用）；URL 可深链（`name` / `status` / `member_id`）。

卡片栅格（成员量级：个位数）：

| 元素 | 内容 |
|------|------|
| 名称 | `name`（+备注） |
| 状态 | active / disabled 徽章 |
| 令牌签发时间 | `token_issued_at`（提示「明文已不可找回，如需新令牌请重发」） |
| 名下 key 数 | 聚合计数（hover 列出 key 名） |
| 操作 | 编辑 / 重发令牌 / 停用（或启用）/ 删除（见 §5 条件） |

## 2. 开户

表单：名称（必填、唯一性校验）、备注（可空）→ 提交 → **自动生成令牌** → 明文展示对话框（见 §3）

## 3. 档案修改（名称 / 备注）（R16）

- **入口**：卡片操作「编辑」→ 小对话框（或行内编辑，实现期定）
- **可改字段**：名称（必填、唯一性校验）、备注（可空）——**仅此两项**
- 不含启停、不含令牌（各自走 §4 / §5 / 既有重发）；`created_at` 等只读展示
- 名称冲突提示与开户一致（「名称已被占用」）
- 典型场景：误建/占位名 → 挂 key 前改名；已发出令牌时改名优于删除重建（重建会作废旧令牌）

## 4. 令牌签发与重发（敏感操作的标准交互）

**明文展示对话框**（开户自动触发，或重发触发）：

- 令牌明文 + 复制按钮（点击即复制 + 「已复制」反馈）
- 醒目警示：「**关闭后将无法再次查看**——请立即复制并通过你信任的渠道发给成员」
- 关闭需二次确认（「我已保存并发送」按钮）
- **重发**的确认弹窗先行：「重发后旧令牌立即失效（该成员正在用的访问将中断）」→ 确认 → 新明文对话框
- 对话框关闭后，界面任何地方不再出现明文（库里只有哈希——members 3.1）

## 5. 停用 / 启用 · 空壳删除

**停用 / 启用**：

- 停用：确认弹窗「停用后该成员的视图立即不可访问（令牌验证含状态检查）；数据保留」——退拼 / 令牌疑似泄露的标准动作
- 启用：直接启用（下一请求即恢复）
- 软删除语义仍是账本实体默认：名下有 key 的成员**只有停用**（members 3.4）

**空壳删除（R16）**：

- **条件**：仅 `key_count = 0` 时露出「删除」；名下有 key 则隐藏或禁用并提示「名下仍有 key，只能停用」
- 确认弹窗：「删除后不可恢复（名称与令牌一并作废）；仅清理未挂 key 的空壳」→ 删除
- 典型场景：误建、从未使用的开户行——清壳，避免停用行越积越多

## 6. 空态

「还没有成员——为每位分摊朋友开户并发放访问令牌」
