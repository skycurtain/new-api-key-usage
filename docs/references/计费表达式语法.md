## 0. 为什么需要这份清单

表达式由上游**保存前编译校验**过，因此日志里出现的每一条都是合法的。这决定了两件事：

1. 不存在「上游表达式写错了」这种情况，验算端读不懂只可能是**自己**的问题。
2. 想与上游算得一样，就必须复刻它的**优先级与结合性**。这类差异不会报错，只会静默算错——所以数值不能靠直觉，只能照抄源码。

出处均为实测源码，不给行号，按「文件 + 符号」定位。

### 0.1 基线分工：`expr.md` 管语义，源码管语法

上游把这份 DSL 的承诺拆在两处，缺一不可：

- **`expr.md` 定义语义与环境**：有哪些变量与函数、`p`/`c` 怎么自动排除、`len` 怎么算、`fixed()` 与 `v1:` 各是什么含义、配额怎么换算。
- **语法只能以 expr-lang 源码为准**：`expr.md` 通篇**没有运算符优先级表**，只有一句 *Powered by expr-lang/expr*。优先级、结合性、字面量形式、注释全在 `parser/` 包里。

所以只在 `expr.md` 上做验证会漏掉优先级——而优先级错了不会报错，只会静默算错。§1 那几条反直觉结论就是证据。

## 1. 优先级与结合性

数值取自 `parser/operator/operator.go` 的 `var Binary` / `var Unary`；调度在 `parser/parser.go` 的 `(*Parser).parseExpression`。

| 优先级 | 结合性 | 运算符 |
|---:|---|---|
| 0 | 左 | pipe `\|`（把左值作为首个实参注入右侧标识符） |
| 10 | 左 | `or` `\|\|` |
| 15 | 左 | `and` `&&` |
| 20 | 左 | `==` `!=` `<` `>` `>=` `<=` `in` `matches` `contains` `startsWith` `endsWith` |
| 25 | 左 | `..`（区间） |
| 30 | 左 | `+` `-` |
| 60 | 左 | `*` `/` `%` |
| 100 | **右** | `**` `^` |
| 500 | 左 | `??` |

一元运算符**共用同一套数值**（`parsePrimary` 以 `parseExpression(op.Precedence)` 解析操作数，故可直接与上表比较）：

| 优先级 | 运算符 | 后果 |
|---:|---|---|
| 90 | 前缀 `-` `+` | 低于 `**`(100)、高于 `*`(60) |
| 50 | 前缀 `not` `!` | 高于 `in`(20)、**低于** `*`(60) |

四条反直觉、照抄才对的结论：

```
-2 ** 2      →  -(2 ** 2)        = -4      （一元 - 是 90，幂是 100）
-a * b       →  (-a) * b                   （90 > 60）
not a * b    →  not (a * b)                （not 是 50 < 60）
not a in b   →  (not a) in b               （not 50 > in 20）
```

## 2. 不占优先级数值的语法形式

| 形式 | 解析入口 | 绑定松紧 |
|---|---|---|
| 三元 `? :`、Elvis `?:` | `parseConditional`，仅 `precedence == 0` 时调用 | 比所有二元运算符都松；**右结合** |
| `let x = e; body` | `parseVariableDeclaration` | 语句级，最低 |
| `if c { … } else { … }` | `parseConditionalIf` | 语句级 |
| `;` 表达式序列 | `parseSequenceExpression` | 最外层，允许尾随 `;` |
| 后缀 `.` `?.` `[]` `()` 与切片 `[a:b]` | `parsePostfixExpression` | 无优先级数值，绑定最紧 |
| `#` `#name` 与谓词内的 `.` | `parsePrimary`（`p.depth > 0`） | 仅谓词上下文 |

三元的两条结合规则：

```
a ? b : c ? d : e   →  a ? b : (c ? d : e)     右结合
a ? b ? c : d : e   →  a ? (b ? c : d) : e     中间分支独立配对
a ?: b              →  a ? a : b               Elvis，等价于条件自身
a ?? b ? c : d      →  (a ?? b) ? c : d        三元比 ?? 松
```

## 3. 词法

`Kind` 只有六种：`Identifier` · `Number` · `String` · `Bytes` · `Operator` · `Bracket`（外加 `EOF`）。**关键字不是独立 Kind**，靠 `Token.Value` 区分（`parser/lexer/token.go`）。

### 3.1 关键字

| 词 | 词法归类 | 说明 |
|---|---|---|
| `not` `in` `or` `and` `matches` `contains` `startsWith` `endsWith` `let` | Operator | `true` / `false` / `nil` 例外，见下 |
| `if` `else` | Operator | `DisableIfOperator = true` 时降级为 Identifier（兼容自定义 `if()` 函数） |
| `true` `false` `nil` | **Identifier** | 由 `parseSecondary` 按字符串特判成 `BoolNode` / `NilNode` |

谓词类内建名（`all` `none` `any` `one` `filter` `map` `count` `sum` `find` `findIndex` `findLast` `findLastIndex` `groupBy` `sortBy` `reduce`）**不是关键字**，是 `parser.go` 的 `var predicates`，由 `parseCall` 按参数形状特判。

### 3.2 标识符

首字符：`_` `$` 或 `unicode.IsLetter`；后续：字母、数字、`_`、`$`。
属性名放宽：`.` 后面允许 Operator 类 token（源码注释原文 *Operators like "not" and "matches" are valid methods or property names*），故 `a.not`、`a.matches` 合法。

### 3.3 运算符切分

`parser/lexer/state.go` 的 `root` 状态：`,` `;` `%` `+` `-` `^` 单字符成 token；`&` `!` `=` `*` `<` `>` 之后机械地多吞一个同组字符（故可能产出 `&&` `==` `!=` `>=` `<=` `**`），**lexer 不校验合法性**，查不到运算符时才由 parser 报 `unexpected token`。

`?` 一族的产出由状态决定：`?` / `?.` / `??` 三种。`.` 一族：`.` / `..`，且 `.` 后若紧跟数字则回退交给数字状态（支持 `.5`）。

### 3.4 数字

十进制 · `_` 分隔符（解析前剔除）· `0x`/`0X` · `0o`/`0O` · `0b`/`0B` · 小数 `1.5` · 前导点 `.5` · 指数 `1e9` `1E-3`。

`1..2` 的区间**不会被吞成小数**：`scanNumber` 若在 `.` 后 peek 到第二个 `.`，会把整个点回退。

`parseSecondary` 的分流顺序（先命中者胜）决定了两个边界行为：`0x1e5` 走十六进制（先命中前缀分支），而 `0b1e` 因含 `e` 会先落进浮点分支报 `invalid float literal`。

### 3.5 字符串与字节

| 形式 | 规则 |
|---|---|
| `'…'` `"…"` | 支持转义；**不允许裸换行**（`literal not terminated`） |
| `` `…` `` | 原始串，不处理转义；双写反引号表示一个字面反引号 |
| `b'…'` `b"…"` | 字节串；**拒绝** `\u` / `\U`，只允许 `\x` 与八进制等字节级转义 |

转义是两阶段：`scanEscape` 是**闸门**（`\a \b \f \n \r \t \v \\` + 当前引号 + 八进制 + `\x` + `\u`/`\u{…}` + `\U`），实际解码在 `unescapeChar`。因为闸门先跑，**可接受集合由闸门决定**——`unescapeChar` 表里更大的部分（`\?`、`\X`、双引号串里的 `\'`）在词法阶段就被拒了。

带引号字符串解码前统一做换行归一化（`\r\n`、`\r` → `\n`）。

### 3.6 注释

`//` 到行尾；`/* … */`，未闭合报 `unclosed comment`。注释不产生 token。

## 4. 求值环境

`pkg/billingexpr/run.go` 的 `RunExpr` 把下列名字塞进 env，**全部是 `float64`**（`tier` 的签名为 `func(string, float64) float64`，表达式结果也必须是 `float64`）。

### 4.1 变量（13 个）

| 变量 | 含义 |
|---|---|
| `p` | 输入 token 数（**计价用**），自动排除表达式单独计价的子类 |
| `len` | 输入上下文总长度（**条件用**），不受自动排除影响 |
| `cr` | 缓存读 token |
| `cc` | 缓存写 token（Claude 5m / OpenAI 30m / 通用） |
| `cc1h` `cc12h` | 1 小时 / 12 小时缓存写（Claude / OpenAI 分属） |
| `img` `img_cr` `img_o` | 图片输入 / 图片缓存读 / 图片输出 |
| `ai` `ao` | 音频输入 / 音频输出 |
| `c` | 输出 token 数，同样自动排除子类 |
| `image_count` | 图片数量（按次乘数，非 token） |

`p` / `c` 的自动排除是**按表达式实际引用了哪些变量**决定的（编译期走 AST 收集），且 `len` 永不参与排除。

### 4.2 函数

| 函数 | 上游绑定 | 备注 |
|---|---|---|
| `tier(name, value)` | 闭包，记录 `MatchedTier` 后原样返回 `value` | 必须包住计费表达式；档名只用于展示 |
| `fixed(amount)` | 闭包，返回 `amount * 1_000_000` | 按次计费；切 `BillingUnit = request` |
| `max` `min` `abs` `ceil` `floor` | `math.Max` / `Min` / `Abs` / `Ceil` / `Floor` | 与 JS `Math.*` 逐位一致 |
| `param(path)` | 读请求体（ojson / gjson 路径） | 依赖请求上下文 |
| `header(key)` | 读请求头（小写、trim） | 依赖请求上下文 |
| `has(source, substr)` | `strings.Contains(fmt.Sprint(source), substr)` | 依赖请求上下文 |
| `hour` `minute` `weekday` `month` `day` | `time.Now().In(loc)`，tz 缺省 UTC | 依赖当前时间 |
| `u(name)` | 读任务用量事实 | 依赖任务上下文 |

另有内部追踪函数名（`requestRuleTraceFunction` / `requestRuleTraceIntFunction`），属于保留名，不能出现在存储的表达式里。

### 4.3 结算换算

```
token 计费： quota = eval(expr) / 1_000_000 × QuotaPerUnit × groupRatio
task  计费： quota = eval(expr)               × QuotaPerUnit × groupRatio   （不除 1e6）
```

取整与 `int32` 饱和见 [`NewAPI-用量计算链路.md`](NewAPI-用量计算链路.md)。

## 5. NewAPI 自己的两条拼接约定

这两条**不属于 expr-lang**，是上游在编译表达式之前做的预处理。读日志里的表达式时必须先认出来。

| 约定 | 位置 | 内容 |
|---|---|---|
| 版本前缀 `v1:` | `pkg/billingexpr/compile.go` | 正式格式是 `v1:tier(...)`；无前缀等同 v1。前缀控制编译环境、归一化与换算公式 |
| 请求条件倍率 `\|\|\|` | `compile.go` / 编辑器 `combineBillingExpr` | 存储值 = 计费表达式 + `\|\|\|` + 条件倍率。编译前先按 `\|\|\|` 切开，再把倍率改写成 `(tier(...)) * (cond ? n : 1)` 拼回去 |

## 6. 边界（源码未覆盖）

以下内容本轮**没有**从源码确认，不要当成事实使用：

- `**` 的运行时语义（操作数类型、整数溢出、`^` 与 `**` 在 VM 层是否有差别）——只读了语法层，未读 `vm/` `compiler/` `builtin/`
- 优先级与 `??` 对类型检查的影响（`compiler/` 未读）
- Elvis 形式下 `ConditionalNode.Exp1` 与 `Cond` 是否同一指针（未读 AST 定义）
- `parser_test.go` / `lexer_test.go` 未读，本文不含测试期望值佐证，全部结论基于实现代码

另有一处**与旧记录不符的更正**：常被引用的 `const ( lowest, ternary, coalesce, or, and, … )` 优先级常量块在 v1.17.8 的 `parser/parser.go` 中**不存在**，优先级实际是 `parser/operator/operator.go` 里的整数字面量。若需要更早版本的常量块形态，需另取对应 tag。
